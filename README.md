# Interfere Terraform provider

Manage existing workspace settings, network rules, tracking domains, verified domains, SCIM group role mappings, and workspace API keys with Terraform Plugin Framework and a Fern-generated Go client. Install it from the [Terraform Registry](https://registry.terraform.io/providers/interfere-inc/interfere/latest).

SDK setup uses a workspace secret and a stable service name. Supply the secret as `INTERFERE_API_KEY` to the framework build plugin, with `release:write`; the plugin registers the service's release, bakes a release token into the browser bundle and handles source maps automatically. Server telemetry needs `org:telemetry:write`. Keep workspace secrets out of browser code. The provider's own management credential is `INTERFERE_TOKEN`.

| Resource                             | Behavior                                                                                                                                                                  |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `interfere_workspace`                | Adopts an existing workspace and manages its name, slug, and security settings. Destroying removes Terraform management without deleting the workspace.                   |
| `interfere_service`                  | Adopts an existing service by UUID and manages its type and website settings, including services without an App. Destroying preserves the service and retained telemetry. |
| `interfere_tracking_domain`          | Provisions a tracking hostname and exposes DNS/TLS verification status.                                                                                                   |
| `interfere_network_rules`            | Replaces the full list of networks allowed to reach the workspace dashboard and API. Destroy removes every restriction.                                                   |
| `interfere_verified_domain`          | Adds a workspace email domain, sets its enrollment mode, and exposes verification status.                                                                                 |
| `interfere_scim_group_role_mappings` | Maps a SCIM directory's groups to workspace roles in precedence order. Destroy unmaps them.                                                                               |
| `interfere_private_key`              | Creates and revokes workspace keys with explicit scopes and optional expiry. Configuration changes replace the key.                                                       |
| `interfere_public_key`               | Legacy public-key management for older SDK deployments; not needed for new setup. External rotation refreshes the current value.                                          |

## Install

```hcl
terraform {
  required_providers {
    interfere = {
      source  = "interfere-inc/interfere"
      version = "~> 0.5.0"
    }
  }
}

provider "interfere" {}
```

Set `INTERFERE_TOKEN` through your shell or secret manager, then run `terraform init` and `terraform plan`. The credential needs the permissions described below for the resources you manage.

## Generate and test

Building and testing requires Go 1.26 or newer and Terraform. The public repository includes generated Go code, so `make build test check` works without Fern or Docker.

Regeneration additionally requires Docker and Bun. `make generate` runs stable Fern CLI 5.193.2, also pinned in `fern/fern.config.json`, with Go generator 1.70.16. Local generation does not require an enterprise entitlement. The provider uses the OpenAPI bearer security scheme directly. The separate public CLI retains its Fern snapshot because stable Fern does not support its per-endpoint multi-auth configuration.

Copy the Gateway Terraform OpenAPI 3.1 publication into the provider's generation input:

```sh
cp /absolute/path/to/openapi-terraform-3.1.json openapi.json
make generate
make build test check
```

All resource and data-source schemas are generated by HashiCorp's pinned OpenAPI and Framework generators. Field descriptions originate in the canonical API schemas and pass through `openapi.json` into the Go schemas and registry documentation. The intermediate code spec is a disposable build artifact. `generator_config.yml` maps resource operations; it does not duplicate field descriptions. Small Go adapters preserve the existing flat Terraform fields, configuration flags, secret sensitivity, and lifecycle rules. Field types and API descriptions come from generation; Terraform-only behavior remains in Go.

`make generate` regenerates the Fern client, resource and data-source schemas, and documentation. `make generate-schemas` needs only Go; `make docs` also needs Terraform. `make check-generated` regenerates schemas and docs and fails on tracked differences. `openapi.sha256` records the publication's SHA-256 checksum, and the API's contract test verifies it against the current API. The full OpenAPI document and SDK are generated locally and included in public source snapshots. Generated files must not be edited manually.

Go dependencies are locked in `go.mod` and `go.sum`. Tests use Terraform with local HTTP fixtures and do not create remote resources. They cover schema documentation, the existing workspace contract, explicit and automatic creation identities, replacements, imports, retry recovery, and permission failures.

Fern consumes the API export unchanged. Terraform schemas declare replacement rules and project the created private-key secret into a sensitive attribute.

## Try the local binary

Create a separate Terraform CLI configuration file with the absolute path to the built binary's directory:

```hcl
provider_installation {
  dev_overrides {
    "interfere-inc/interfere" = "/absolute/path/to/terraform-provider-interfere/bin"
  }
  direct {}
}
```

Set `TF_CLI_CONFIG_FILE` to that file. Set `INTERFERE_TOKEN` through your shell or secret manager to a workspace API key with the permissions your configuration needs, such as `org:workspace_basics:read` and `org:workspace_basics:write`. Session and delegated OAuth access tokens also work. Release-only keys cannot manage workspace resources.

Create a workspace key through `POST /v3/workspaces/{workspaceSlug}/api-keys` using an authenticated workspace user with `org:api_keys:write` and the permissions being granted:

```json
{
  "idempotencyKey": "11111111-1111-4111-8111-111111111111",
  "name": "Terraform",
  "scopes": ["org:workspace_basics:read", "org:workspace_basics:write"],
  "secondsUntilExpiration": null
}
```

Use a fresh UUID for each key creation. Set `secondsUntilExpiration` to a positive integer for an expiring key, or `null` for no expiry. Both grants fields are required. The response includes `apiKey.secret`; store it in your secret manager. Revoke the key with `DELETE /v3/workspaces/{workspaceSlug}/api-keys/{apiKeyId}`. Key access is limited to its explicit scopes and the creator's current workspace permissions. Removing the creator's membership removes the key's management access.

## Existing workspace settings

Use `examples/workspace/main.tf` with an existing workspace slug. The first apply adopts that workspace and sets its name. Later changes to `workspace_slug` rename it. The ID stays unchanged, and `data_residency_location` is read-only. Destroying the resource leaves the workspace and its current settings intact. This resource never calls workspace creation or deletion APIs.

The provider credential needs `org:workspace_basics:read` and `org:workspace_basics:write`. Prefer a workspace API key for slug changes; a session token carrying the old slug needs to be refreshed afterward.

```sh
terraform import interfere_workspace.team existing-workspace
```

### Security settings

`interfere_workspace` also manages member workspace creation, Interfere support access, and sign-in methods. Omit an attribute to keep its current value; destroying the resource leaves every setting as it is.

- `allow_member_workspace_creation` controls whether members can create more workspaces. It needs `org:workspace_basics:write`.
- `impersonation_granted` turns support access on or off. `impersonation_expires_at` ends it at a Unix-millisecond time. When `impersonation_granted` is configured, an omitted expiry means access does not expire. After the expiry passes, `impersonation_granted` stays `true` but access is no longer effective. Set a new expiry or `false` to change it. Support access needs `org:workspace_basics:write`.
- `enabled_auth_methods` is the set of allowed sign-in methods and must include `passkey` and `email_code`. It needs `org:workspace_auth:write`. The change is applied through the identity provider and appears in reads after its webhook is processed, usually within seconds. A plan run immediately after apply can therefore show the previous value once.

These operations are published only to the Terraform contract, not to MCP or the CLI. They accept workspace API keys and session tokens but reject delegated OAuth access tokens.

## Service settings

Use `interfere_service` with `workspace_slug` and the existing service UUID in `id`. Optional `type` and `website_settings` manage the service directly. Omitted settings retain their current values; supplying `website_settings` replaces its full object. No App or credentials are created. Reads need `org:integration_settings:read`; changes need `org:services:write`.

`data.interfere_service` looks up one service by UUID. `data.interfere_services` lists up to 500 services ordered by namespace, name, and ID. Use the singular lookup for identities outside that list.

Import with `terraform import interfere_service.website workspace-slug/service-uuid`. To replace an existing `interfere_surface`, stop managing it with a `removed` block and `lifecycle { destroy = false }`, and adopt the service with an `import` block; see the upgrade instructions in `CHANGELOG.md`.

## Private keys

See `examples/private-key/main.tf` for workspace API access and release keys. Set `seconds_until_expiration` to a positive number of seconds, or omit it for no expiry. The `expires_at` output is Unix milliseconds or null.

Keys require `org:api_keys:read` and `org:api_keys:write` on the provider credential. The credential must also hold every permission being granted.

The computed `secret` attribute is sensitive and stored in Terraform state. Use a protected state backend. Import reads metadata only and leaves `secret` null:

```sh
terraform import interfere_private_key.api existing-workspace/11111111-1111-4111-8111-111111111111
```

For an imported key, match its scopes and lifetime in configuration. Omit `idempotency_key` for automatic creation and replacement UUIDs. Existing explicit UUIDs remain supported; removing one from configuration preserves the managed key. If you keep an explicit UUID, change it for each replacement. The provider rejects configuration changes that would reuse the old creation UUID before revoking the existing key. Use a different name when requesting `create_before_destroy`, because active key names are unique within their workspace.

Refresh never fetches a secret. External rotation of a key created by Terraform reports an error instead of presenting the old secret as current; import it for metadata-only management or replace it with a new key.

## Legacy public keys

Public-key setup is deprecated. `interfere_public_key` remains available for older deployments that still need it; new browser builds use the release token from a workspace-secret build. Do not remove a key still used by a deployed bundle. Creation and revocation require `org:workspace_auth:write`; refresh and import require `org:workspace_auth:read` or the legacy `org:surfaces:read` permission.

The `surface_slug` attribute on `interfere_public_key` and `interfere_private_key` was deprecated in 0.x and is removed in 1.0. New keys are workspace-scoped. Follow the [upgrade guide](CHANGELOG.md#upgrading-from-0x) before upgrading existing state.

Import an existing key without changing its value:

```sh
terraform import interfere_public_key.browser existing-workspace/11111111-1111-4111-8111-111111111111
```

Match the imported key's name and omit `idempotency_key` for automatic creation identities. External rotation updates `content` on refresh. Changing the name or workspace replaces the key. Use a distinct name with `create_before_destroy`. Revocation removes the resource from state. Destroy revokes the current value and its rotation grace-period values, which affects every service using it.

## Read and deletion behavior

Private keys leave state on explicit revocation/expiry or a declared key-not-found response. Permission failures, outages, malformed responses, and unexpected resource identities preserve state and report an error. Workspace queries can return `null` when permissions are insufficient, so an empty result cannot safely mean deletion.

Idempotent creation requests use Fern's native retry handling, with at most three attempts for retryable HTTP responses and the same UUID and body on every attempt. Other operations disable HTTP retries. Rename and delete acknowledgements must contain `success: true`. API response bodies are excluded from diagnostics because they can contain credentials.

If creation fails after retries, or a transport error leaves its result uncertain, the diagnostic includes its non-secret creation UUID. Set `idempotency_key` to that value before applying again to recover the same operation. The provider does not promise recovery after a process crash before Terraform saves state or the diagnostic is returned; inspect the remote resource before retrying in that case.

## Releases

Record user-facing changes in `CHANGELOG.md` before tagging, with an upgrade guide for every breaking change.

Development happens in Interfere's private source repository. This repository holds the provider source and its generated Go code, with a separate Git history. Infrastructure provisions the repository, Engineering access, and branch protection.

Each change to the provider source arrives on the `source-sync` branch. The `Source sync` workflow regenerates `openapi.json`, `internal/sdk`, the resource and data-source schemas, and the documentation against the deployed API, opens a pull request and runs `Check`. Release state (`CHANGELOG.md`, `package.json`, `.changeset`) and the release scripts live only in this repository.

The public repository's release workflow builds eight OS/architecture combinations when a `v*` tag is pushed. It signs SHA-256 checksums with the dedicated `GPG_PRIVATE_KEY` and `PASSPHRASE` repository secrets, and creates a draft release. Verify its artifacts before publishing. Register the matching public signing key and provider in HCP Terraform once; subsequent published releases notify the registry through its webhook.

Before publishing a release, deploy the corresponding API changes and run acceptance tests against a disposable workspace.

## Tracking domains

Use `interfere_tracking_domain` with a lowercase hostname. The credential needs `org:workspace_domains:read` and `org:workspace_domains:write`. Configure a DNS-only CNAME from `name` to the computed `cname_target` through your DNS provider.

Creation returns while verification is pending so the DNS record can depend on this resource. `status` and `ssl_status` refresh as the service processes verification. Apply completion does not mean DNS or TLS is active. The resource manages the workspace hostname, not DNS records.

Import using `workspace-slug/domain-UUID`. Omit `idempotency_key` to generate UUIDs automatically when replacing or recreating a deleted domain. Name and workspace changes require replacement. Destroy removes the hostname registration and its managed TLS provisioning.

## Network rules

Use `interfere_network_rules` to manage the networks allowed to reach a workspace dashboard and API. Each rule has a `label` and a `value`: a CIDR range in canonical form, such as `203.0.113.0/24`, `198.51.100.7/32` or `2001:db8::/32`, or an ASN such as `AS13335`. Plan rejects other spellings and suggests the canonical one, so applied state never drifts from configuration. The list holds at most 100 rules and each network may appear once.

The resource owns the complete list. Each apply replaces every rule in the workspace, including rules added in the dashboard. Rules whose value is unchanged keep their identifiers, so ASN approvals are preserved. Non-empty lists require the Enterprise plan. The credential needs `org:workspace_auth:read` and `org:workspace_auth:write`.

**Destroying the resource saves an empty list and removes every network restriction.** Removing the resource from configuration does the same. To stop managing the rules without clearing them, use a `removed` block with `lifecycle { destroy = false }`.

**Keep the Terraform runner's egress in the list.** The API rejects a save that would block the network the request comes from. If the runner's egress IP address later falls outside the list, Terraform can no longer read or update the rules until an administrator on an allowed network adds it in the dashboard.

Import using the workspace slug:

```sh
terraform import interfere_network_rules.workspace existing-workspace
```

## Verified domains

Use `interfere_verified_domain` with a lowercase email domain, such as `example.com`, to control how people with an address at that domain join the workspace. The credential needs `org:workspace_domains:read` and `org:workspace_domains:write`.

Creation returns while verification is pending. A workspace admin verifies the domain in the dashboard; `verification_status` and `verified_at` refresh on the next plan. `enrollment_mode` defaults to `manual_invitation`. The automatic modes, `automatic_invitation` and `automatic_suggestion`, require a verified domain, so the provider rejects them on creation and on an unverified domain before calling the API. Create the domain with `manual_invitation`, verify it, then change `enrollment_mode`. Domains managed by an enterprise SSO connection are rejected.

Import using `workspace-slug/domain-name`. Name and workspace changes require replacement. Destroy removes the domain from the workspace and from the sign-in service.

## SCIM group role mappings

Use one `interfere_scim_group_role_mappings` per SCIM directory. `mappings` lists each group's `scim_group_id` and `role` in precedence order: when a member belongs to several mapped groups, the earliest mapping wins. The resource owns every role mapping in the directory, so groups left out of `mappings` lose their role, and destroy removes the role from every mapped group. The credential needs `org:workspace_auth:read` and `org:workspace_auth:write`, and cannot grant a role above the caller's own.

Groups appear after the identity provider provisions them; mapping a group that has not been provisioned fails before any change. Reordering requires group role mapping to be turned on for the directory. Creating the directory, its connection and its SCIM bearer token stays outside Terraform. The provider reads only group rows, never the directory, so the token never enters state.

Import using `workspace-slug/directory-id`.

Domain and SCIM role operations are published only to the Terraform contract, not to MCP or the CLI. They accept workspace API keys and session tokens but reject delegated OAuth access tokens.

## Data sources

`data.interfere_workspace` looks up workspace identity, name, residency, and security settings with `org:workspace_basics:read`. It does not take ownership of the workspace.

`data.interfere_public_keys` lists legacy workspace publishable keys for older deployments. Public-key setup is deprecated; new SDK builds use a workspace secret and a build-minted release token. Listing requires `org:workspace_auth:read` or the legacy `org:surfaces:read` permission. Results include `content`; private keys never enter these data sources. A credential without the read permission sees an empty workspace list, so check permissions before relying on an empty result.

`data.interfere_tracking_domain` looks up a tracking hostname by `name` and exposes its identity, verification and TLS status, and `cname_target`, with `org:workspace_domains:read`. A missing or inaccessible hostname produces an error. Verified enrollment domains are not returned.

`data.interfere_integration` looks up an installation using `integration_provider` and requires `org:integration_settings:read`. When multiple installations match, set `integration_id` explicitly. Missing, ambiguous, or inaccessible results produce an error. Only installation identity, provider, and status enter state; installation credentials and provider metadata do not.
