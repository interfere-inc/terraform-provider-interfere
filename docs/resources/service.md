# interfere_service (Resource)

Manage an existing service's type and website settings. Applying adopts the service by ID. Destroying only removes Terraform management and preserves the service, settings, credentials, and telemetry. Import using workspace-slug/service-uuid.

The provider credential needs `org:integration_settings:read` and `org:services:write`. The service can exist without an App. Omit `type` or `website_settings` to preserve the current value. When supplied, `website_settings` replaces the complete service settings object, including the plugin overrides. Omitted plugin overrides use the SDK defaults.

## Example Usage

```terraform
resource "interfere_service" "website" {
  workspace_slug = "example"
  id             = "75000000-0000-4000-8000-000000000001"
  type           = "website"

  website_settings = {
    anonymous_replay_policy = "on_error"
    anonymous_user_tracking = false
    environment_filtering   = true
    plugins = {
      replay = true
      logs   = false
    }
  }
}
```

## Migrating from `interfere_surface`

Provider 1.0 has no `interfere_surface` resource and cannot move its state. With Terraform 1.7 or later, replace the old resource configuration with `interfere_service`, set `id` to the service UUID that replaced the App (find it with `data.interfere_services`), and add:

```terraform
removed {
  from = interfere_surface.website

  lifecycle {
    destroy = false
  }
}

import {
  to = interfere_service.website
  id = "example-workspace/00000000-0000-4000-8000-000000000000"
}
```

The `removed` block stops managing the old resource without deleting anything, and the `import` block adopts the service. Plan and apply, then delete both blocks. The upgrade creates no App, credential, or service, and never deletes retained telemetry.
